# 笔触选择记录与核对

新版随“自动跟随”启动独立卡片采集。继续用项目根目录的 `启动.bat` 启动，无需重新打包。源码更新后需正常重开工具一次；之后游戏窗口移动、缩放不需要重启或手动调坐标。

## 保存什么

- 每组两张卡片使用独立 `choice_id`，方向阶段与效果阶段分开。相同效果连续选择两次，保留两次记录。
- 先保留卡片局部图，再由单个后台 OCR 工作线程识别。正文读完时即使已换局，也只更新原来的选择编号。
- 卡片保持物理槽位：上卡未识别、下卡识别成功时，下卡仍是第二张，不挤到第一张。
- 确认选择需要选卡点击、确认按钮点击、随后卡片关闭或切换。关闭窗口、切走游戏、停止采集、只有候选文字均不算确认。确认后超过 5 秒才消失的面板保留为待核对。
- `canonical_affix_id` 保存效果的语义标识。`brush_effect_ids` 保存官方表候选；只有唯一候选时才填写标量 `brush_effect_id`。这是视觉文字到配置表的映射，不是抓包收到的真实协议 ID。
- `effect` / `effect_id` 记录调色效果；`brush_effect` / `brush_effect_id` 记录单独的笔触效果正文及候选，不再混用。当前颜料面板读到笔触正文时可做独立核对。
- 有棋盘点击、当前颜料锚点及颜料读数一致时，记录落点关联；没有证据就留空。关联不等于游戏提供了唯一颜料实例 ID。范围内升级仍由复盘中的前后棋盘读数比较，不把变化自动归因为该笔触。

卡片采集仅在游戏是前台窗口时运行，且先验证当前画面的棋盘和卡片边界。不会抢焦点、点击游戏或保存整屏。缩放时重新测量当前帧，点击保留点击发生时的窗口尺寸，避免旧坐标套到新窗口。默认节拍为约 120 ms，实际速度取决于采集和定位耗时；短到没有被采样到的卡片仍可能漏记。

## 空间与准确率门槛

默认 `brush_recording.mode = validation`，只保存卡片裁剪 WebP，不录制视频。每组卡片最多保留两个采样时刻，每次两张裁剪图，内容相同的图片去重。图片累计上限由 `brush_recording.max_image_mb` 控制，默认 **128 MiB**。

达到上限后停止新增图片，继续识别和写入小型 JSON；状态栏会提示“笔触图片已达上限”。不会自动删除旧图或原有游戏存档。该限制针对新目录中的图片，现有 `runtime` 日志和历史截图不计入此额度。

后续可把配置设为 `brush_recording.mode = id_only`。程序必须通过人工核对门槛才接受该设置，否则继续验证模式并提示待核验。ID 模式停止保存新图及原始 OCR 行，保存语义 ID、官方候选 ID、选择槽位、时刻和来源。已有验证图保留，清理应在核对结束后另行处理。

准确率按完整的实际选择计算，未识别及漏记都计入错误。判定包括效果、卡片槽位和官方候选集合，不使用 OCR 相似分作为准确率。当前采用保守门槛：至少 300 次人工核对、覆盖至少 10 局与 3 种窗口尺寸，且准确率的 95% Wilson 下界不低于 99%。即使全部正确，也需要约 381 次样本才能通过下界条件。已抽样局中未核对的效果/未知记录会阻止切换。算法版本变化后需要重新核验。

这项门槛支持后续验收，不表示本次改造已达到 99%。同一截图的多次缩放测试不计入真实独立样本。

## 查看和人工标注

工具底部点击 **笔触核对**，生成并打开本地核对页。页面展示每组卡片图、选择结果、官方 ID 候选及详细证据。页面是生成时的快照，再点按钮可刷新。

数据位置：

```text
runtime/brush_evidence/choices/<choice_id>.json
runtime/brush_evidence/images/<内容哈希>.webp
runtime/brush_evidence/reviews.json
runtime/brush_evidence/review.html
```

核对页也可由命令生成：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts\review_brush_evidence.py
```

人工确认某次选择后，在详细证据中取得 `choice_id`，例如确认第二张是“可放置在阻挡地块”：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts\review_brush_evidence.py `
  --choice <choice_id> --expected spread.place_on.blocked `
  --index 2 --official-ids 3010 --reviewer 玩家
```

“作用方向改为对角斜向”应使用官方候选 `1005,4003`，不能人为只挑一个。漏记的真实选择用 `--choice missed-<唯一编号>` 补入核对分母。确实是方向页、取消或并未做选择的页面可用 `--choice <choice_id> --not-choice --reviewer 玩家` 标注排除。人工标签不改写原始预测，也不会把错误预测修改成正确来提高准确率。

## 复盘与限制

新轨迹嵌入精简的 `brush_choices` 证据；局部图及 OCR 原文只在旁文件保存一次。复盘会按精确的录制 session 和选择编号读取晚到的 OCR 结果，并按时间截断未来的确认和落点，旧帧不能提前知道后面的选择。

旧日志里的棋盘效果倒推仍保留作候选诊断；新版真实采集不再把它写成确认选择。旧存档保持原样，没有卡片证据的历史局不会被补成确定选择。当前版本不会主动移动鼠标打开每枚颜料的提示框；提示框未被读到时，独立正文核对和落点关联可能为空。

异常退出时，已写入的待 OCR 图片可以在下次启动恢复识别。未完成确认的页面继续保留为未知。存储异常会显示需检查，并不会阻塞棋盘记录；在只存 ID 模式下，尚未完成 OCR 的内存图片无法在进程异常退出后恢复。

## 本次验证

初步离线结果：8 张实拍卡片页面 × 3 个缩放尺寸，24/24 次定位到棋盘、两张卡片及确认按钮；48 个卡片槽位中 47 个得到严格匹配结果，1 个文字不完整保留未知。另有 65%～120% 连续缩放、非卡片页面、点击几何、迟到结果、重复效果、空间上限和准确率门槛的回归测试。

实时鼠标钩子及实际游戏操作还需要用新版本录制真实局核对，离线结果不能替代这一步，也不足以宣布 99%。

开发验证（2026-11-27）：相关 145 项测试通过；全量运行 1433 项，8 项失败、6 项错误均已在改造前基线出现。随后修正了其中两个笔触测试仍把“纵向最近”写成“纵向随机”的旧预期，相关组复跑通过。剩余既有问题集中在棋盘/背包读数、旧规则目录与宝箱优先级测试；本次不将全量报告描述为全绿。日志保存在 `runtime/protocol_probe/brush_recording_final_suite.log`，最终实拍缩放诊断在 `runtime/protocol_probe/brush_crop_validation_final.json`。
