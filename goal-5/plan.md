# Goal 5 Plan

## Objective

在现有“火炬之光画画拼图助手”基础上，先形成一份以实际代码和运行数据为依据的优化文档，再持续完成不依赖新增游戏截图的关键改造：统一规则数据、建立测试基线、稳定识别到推荐的状态流、让桌宠本体瞬移提示 Top1、补齐稳健/均衡/搏高分的学习与评估、建设隐私友好的多用户数据协议。只有完成这些工作并确认仍存在无法用现有素材解决的识别缺口后，才整理截图采集清单。

## Confirmed Direction

- 工具保持被动辅助：不自动点击、不注入输入、不读取或修改游戏内存。
- 第一版以无边框全屏和窗口化全屏为主要运行方式。
- 桌宠本体负责提示 Top1，移动到点击目标旁边并精确指向；Top2/Top3 仅使用轻量标记。
- 推荐分为硬规则、期望收益、风险成本、资源价值和识别可信度。
- 策略提供稳健、均衡、搏高分三档，不给用户永久贴单一风格标签。
- 学习同时保留高分完整轨迹与普通/失败局轻量摘要，避免幸存者偏差。
- 多用户数据必须明确同意、默认本地、默认不上传截图，并支持版本、去重、校验和回滚。
- 新增截图需求放在最后处理；此前优先复用 `工作簿1.xlsx`、`工作簿1.pdf`、现有 runtime 裁剪和已有游戏截图。

## Current Baseline

- `vision.py` 已覆盖棋盘、当前颜料、背包、笔触和结束信号的启发式识别。
- `game_model.py` 已有规则模拟、放置/笔触/刷新/强制完成评分和结构化解释。
- `desktop_pet.py` 已有独立桌宠与小型穿透标记，但桌宠仍采用固定/手动位置，尚未瞬移到 Top1。
- `learning.py` 已限制真实截图写入，支持 JSONL 轨迹、纠错、统计、导出与合并，但没有自动多用户服务。
- 当前原始轨迹 7 条，按最新可信门槛可用 4 条；有效模仿动作 14 个，笔触、词缀、推荐命中均没有足够样本。
- 工作簿内有 28 张词缀截图和 2 张颜料示例；规则目录包含多个同义描述，需要规范 ID 与识别别名分离。
- 设计文档与实际技术路线存在偏差，且缺少自动化测试；源码运行环境也未统一。

## Architecture Approach

1. 以现有 Python/OpenCV/Tk 实现为基础，不进行无收益的框架重写。
2. 引入明确的游戏阶段与推荐目标模型，将识别事件、决策结果和桌宠表现解耦。
3. 规则层采用稳定规范 ID；OCR/模板识别输出先归一化，再进入概率统计和策略模拟。
4. 推荐保持规则引擎兜底，在数据达到门槛后仅加入有上限的经验先验。
5. 风险模型同时衡量均值、中位数、下分位、方差、高分率、失败率和资源消耗。
6. 多用户数据先建设版本化匿名协议、校验和本地参考聚合，不默认连接任何生产服务。
7. 模型/策略升级采用版本化策略包、影子评估和可回滚加载，不让客户端在线自我修改核心规则。

## Data And Learning Principles

- 区分实际游戏结果、识别结果和工具内部代理分，避免用内部评分反向证明自身推荐正确。
- 记录决策时的完整候选集合、排序、分解得分、用户选择和后续结果，支持 Top1/Top3 与离线策略评估。
- 按 session、匿名安装、游戏版本、识别器版本和策略版本分组，训练/验证不能随机打散同一局步骤。
- 对重复、低置信度、版本不兼容、异常高频和结构不合法的数据拒绝或降权。
- 样本不足时只展示趋势；专家筛选、用户风格和经验加成都必须有最低局数与独立用户数门槛。

## Execution And Validation

- 每轮只执行 `tasks.md` 中第一个未完成任务。
- 业务代码改变后运行相关单元测试、语法/导入检查、编码检查和 diff 检查，并提交小范围 Git commit。
- 每三个任务执行一次综合检查，覆盖需求漂移、识别/状态一致性、UI 安全、数据兼容、安全和回滚。
- Windows/Tk 桌宠行为优先用纯函数和窗口状态 smoke test 验证；需要真实游戏画面的项目留到最后截图评估。
- 不清理或回退当前工作区中不属于本目标的既有修改。

## Risks

- 启发式视觉规则可能在不同分辨率、UI 缩放和特效下失效。
- 桌宠瞬移过于频繁会产生抖动，位于目标中心又可能遮挡信息；需要偏移、迟滞和低置信度冻结。
- 当前样本过少，任何“学习结果”都只能作为趋势，不能替代硬规则。
- 旧 JSONL 记录字段不完整；所有 schema 改造必须向后兼容。
- 自动上传涉及隐私和滥用风险；本目标不部署生产服务、不上传现有数据。
- `app.py`、`vision.py`、`game_model.py` 体积较大，改动应优先新增小模块并保持可回退。

## Rollback

- 新状态机、风险模型、上传协议和策略先验均由配置或默认关闭开关控制。
- 保留现有规则推荐与本地 JSONL 作为离线兜底。
- 新字段只追加不删除，历史记录通过兼容读取器处理。
- 每个实现任务独立提交，出现回归时可按任务回退。

## Default Assumptions

- 不新增或部署远程基础设施；多用户阶段交付本地参考聚合器和可配置、默认关闭的客户端协议。
- 不在数据不足时训练深度学习或强化学习模型。
- 不安装重量级 OCR/ML 依赖，除非现有素材和轻量方案无法达到验收标准。
- 不要求独占全屏覆盖正常工作。
- 截图采集是最终阶段的诊断补充，不作为前置阻塞条件。
