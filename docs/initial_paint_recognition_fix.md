# 初始 / 当前颜料识别修复

实拍证据：`tests/fixtures/current_paint_war_god.png`（1920 × 1020）。面板为「玩法颜料·征战之神 LV3」，横向放置玩法颜料，进度 0/3，提升 1 级。旧版实时结果为怪物 LV3、家族为空、方向和目标未知。

## 已复现的原因

1. Windows OCR 的 `StorageFile.GetFileFromPathAsync` 在当前执行环境返回 `UnauthorizedAccessException`；普通文件读取正常。原实现把错误和“确实没有文字”都转换成空结果，并将空结果缓存。改为普通文件字节 → 内存 WinRT 流 → OCR；错误保留诊断且不缓存，之后相同图片能重试。
2. Windows OCR 将标题分隔符读成全角句点 `．`，原正则只接受 `-·・`。现在兼容句点、冒号和省略分隔符；完整官方家族标题可以独立提供类别与等级，不因规则行暂时缺失而整份丢弃。
3. 原图标裁剪仅含内部红色图案（39 × 40），遗漏蓝色菱形外框。并且外框的菱形判断会被内部 Hough 圆覆盖。现在排除小图案候选，使用完整外框，外框菱形证据优先。

## 防止结果再次被改错

- 通过棋盘尺寸估计搜索区，再用当前画面中浅色横幅的像素确定文字上下边界。识别不到横幅时保留宽搜索兜底；不保存某个窗口尺寸的人工坐标。
- 以文字细节签名识别颜料切换，允许少量位移和光效变化。切换后清空旧文本，并阻止旧的异步请求回写。签名未判为切换的细微进度变化由定期 OCR 更新。
- 最后成功结果超过 1.5 秒仍未刷新时停止复用；换窗口尺寸仍使用现有 generation 隔离。
- 棋盘上旧初始颜料的标记、旧作用范围不再覆盖当前面板已读出的身份、基础等级和方向。
- OCR 恢复后，兼容性检查暴露笔触面板只比较整体亮度的旧缓存问题。笔触卡同步采用文字签名，并使换卡前、看门狗超时前的旧请求失效，避免之前一组卡片的结果覆盖当前卡片。

## 验证

- 实拍问题画面的完整字段恢复正确；不等待 OCR 的首帧也能正确判断玩法和 3 级。
- 9 张已有实拍面板复核通过。横幅自动裁剪后的热 OCR 单次约 0.14–0.29 秒，文字被遮挡而走宽搜索的样本约 0.52 秒。首次独立进程启动包含约 4 秒 Windows OCR 冷启动，仍在后台进行。
- 新增 9 项回归检查：真实 OCR、同一识别器连续缩放、上下留边、标题分隔符、旧棋盘证据冲突、换颜料旧请求、结果过期、OCR 错误重试、相似背景下的笔触换卡旧请求。
- 连续缩放使用 100%、65% + 上下 45 像素留边、130%、80% + 上下 20 像素留边；同一 `VisionTracker` 的最终八项字段全部一致，无需手工标定。
- 扩大回归：184 项，3 项失败、0 错误、0 跳过（`regression_tests_after.txt`）。失败涉及旧金框样本的标记定位，以及两项笔触名称预期差异（“最近 1 个”与“随机”）。内存恢复本次修复前代码后，标记定位和名称映射仍失败；旧版 OCR 不可用导致那项真实笔触截图检查被跳过。没有为让测试通过而改写这些预期或游戏规则。

诊断输出位于 `runtime/current_paint_investigation/`。修改的是 `启动.bat` 使用的 Python 源码，正在运行的旧 Python 进程需要正常关闭并重新启动一次才能载入；之后游戏缩放不需要重启工具。

尝试正常关闭旧助手时，桌面工具两次返回 `failed to activate captured window`，因此未能自动重启。未强制终止当前录制进程；上述验证来自独立进程对实拍截图的真实识别，不表示旧助手已加载新代码。
