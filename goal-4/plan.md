# Goal 4 Plan

## Objective

推进 `J:\tools\huahua\三层高分轨迹方案完成清单.md` 中的未完成事项，并在每完成一项后更新清单标记、记录验证证据和剩余风险。

## Source Checklist

本目标以 `三层高分轨迹方案完成清单.md` 为需求来源。当前未完成重点包括：

- 固定顶层初始字段 `initial_board` / `initial_anchor`。
- 背包从摘要升级为轨迹步骤内压缩明细。
- 候选轨迹/低权重轨迹分类。
- 第二/第三阶段专家样本门槛真正参与筛选。
- Top 10%-20% 专家样本机制。
- 批量模拟评估指标。
- Top3 命中统计。
- 强制/刷新收益 A/B 对比。

## Execution Approach

1. 每个 turn 只执行 `tasks.md` 中第一个未完成任务。
2. 每项任务前完整读取 `goal-4/input.md`、`goal-4/plan.md`、`goal-4/tasks.md`。
3. 优先保持兼容：新增字段、权重和统计，避免删除旧字段或改变历史日志含义。
4. 对真实学习数据路径保持保守：只新增压缩字段或导出/统计逻辑，不引入截图等大体积数据。
5. 每完成任务后运行相关验证，并更新 `tasks.md` 和 `三层高分轨迹方案完成清单.md`。
6. 如代码改变，按技能要求提交代码后再标记任务完成。

## Default Assumptions

- 项目源码统一使用 UTF-8。
- 不要求一次性完成所有清单项；按任务逐项推进。
- 历史 `runtime/*.jsonl` 数据不做迁移，新增逻辑应兼容旧 payload。
- 高风险操作例如删除历史学习数据、改动生产配置、批量重写 runtime 数据不执行。
- 样本筛选优先在导出/统计/权重层实现，避免丢失原始轨迹。

## Validation Strategy

- Python 语法检查：`python -m py_compile ...`
- 编码检查：`python scripts\check_encoding.py .`
- 相关单点 smoke test：用小型 Python 脚本构造 payload 或调用统计函数。
- Git diff review：确认改动范围只覆盖当前任务。
- 清单同步：确认完成项 `[x]` 和完成记录更新。

## Risks

- `app.py` 较大，轨迹 payload 字段新增要避免破坏旧统计。
- 背包明细可能增加日志体积，需要压缩字段。
- 专家筛选如果直接影响保存门槛，可能漏掉未来有用样本；应优先加权/导出筛选。
- 批量模拟评估需要定义指标，可能牵涉策略模型较广，需分阶段落地。

## Rollback

- 每项任务保持小提交，必要时可回退单个任务提交。
- 新增字段采用兼容方式，旧消费者可忽略。
- 不删除历史日志，降低不可逆风险。
