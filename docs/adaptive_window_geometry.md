# 窗口缩放自适应定位

## 2026-11-25 实机测量

坐标单位为截图物理像素。客户区不包含固定高度的标题栏。原图和测量值保存在
`runtime/adaptive_verification/live_before.png`、`live_user_smaller.png` 和
`user_resize_measurements.json`。

| 项目 | 缩小前 | 用户缩小后 |
| --- | --- | --- |
| 完整截图 | 1602 × 939 | 1270 × 807 |
| 客户区 | 1600 × 900 | 1268 × 768 |
| 棋盘 (x, y, w, h) | (231, 235, 571, 570) | (184, 221, 451, 452) |
| 上方卡片 | (881, 399, 519, 99) | (697, 351, 412, 79) |
| 下方卡片 | (881, 509, 519, 96) | (697, 439, 412, 76) |
| 棋盘宽 / 客户区宽 | 35.69% | 35.57% |
| 棋盘高 / 客户区高 | 63.33% | 58.85% |

宽度比例基本稳定，高度比例不固定。两张图符合以下预测模型：16:9 内容等比缩放后在客户区居中。
这只是两种实测尺寸支持的模型，不能作为所有界面、所有宽高比的既定规则。

缩放系数 `s = min(1268 / 1600, 768 / 900) = 0.7925`。
垂直留白为 `(768 - 900 * s) / 2 = 27.375`。
标题栏相对截图的高度为 38 像素。

- 棋盘预测 y：`38 + 27.375 + (235 - 38) * s = 221.4975`，实测 221。
- 上方卡片预测 y：`38 + 27.375 + (399 - 38) * s = 351.4675`，实测 351。
- 下方卡片预测 y：`38 + 27.375 + (509 - 38) * s = 438.6425`，实测 439。

## 实现

1. 通过游戏窗口 HWND/PID 定位窗口，统一使用 DWM 可见边界；额外读取客户区位置，排除标题栏对比例的干扰。
2. `geometry.py` 在当前图像寻找 7 条等间距横线和竖线，原分辨率精修边界，并结合格内纹理和棋盘评分验证。
3. 上一帧棋盘和内容视口提供下一帧搜索初值；初值验证失败时自动全图搜索。识别不依赖手动标定或按每种分辨率写配置。
4. 在棋盘右侧搜索笔触面板，根据两张卡片的明暗分带及共同左右边缘测量实际矩形。卡片中心同时用于推荐指向。
5. 同一 `VisionTracker` 在完整、实时和快速入口都检查尺寸。窗口/采集后端变化或棋盘迁移时清理几何和面板缓存；异步 OCR 使用代次避免旧结果回写。
6. 采集层在尺寸变化后等待 200 毫秒稳定；分析后及界面消费结果前重新检查窗口。拖动中失效的坐标不会作为有效结果发布。
7. 主界面默认自动跟随；“定位预览”只读显示当前棋盘和两张卡片边框，再点关闭。预览透明、鼠标穿透，窗口变化后自动更新。

旧的布局兜底继续保留，新的有效结果带有 `layout.source = image_grid` 和原始截图尺寸。
修复了递归缩略图搜索把原图尺寸诊断错误覆盖为 800 像素的问题。

## 验证

- 针对自适应、采集、面板、推荐坐标和自动跟随的 148 项回归完成：147 项通过，1 项环境条件跳过。
- 同一 tracker 连续处理四个真实尺寸；同尺寸内平移/缩放；两种笔触阶段在 0.5、0.75、1.0、1.25 倍缩放下验证边框；空白和噪声负样本；窗口在分析中变化时不发布/记录；旧 OCR 不覆盖新结果。
- 对真实截图合成 900×1350、2400×700、1400×900 的等比缩放居中画面，在同一 tracker 中自动重新找到棋盘，不读取标定。此项验证不同宽高比的算法行为，并非游戏真实窗口连续拖拽实测。
- 全量运行 1341 项：当时出现 7 个失败、8 个错误、5 个跳过。13 个功能失败/错误用 HEAD 模块复现；另一项旧源码结构断言所检查函数与 HEAD 的 AST 一致。耗时测试受单帧抢占和面板 OCR 后台任务影响，现与同文件其他性能测试一致：隔离异步 OCR，并取三次耗时最小值，保留每次识别正确性断言。修改后的相关回归已通过；未重新执行全量套件。
- 用户手动缩小的两张真实窗口图验证了比例预测；常驻采集脚本在缩小后的窗口读到棋盘及“堆砌 / 扩散”。自动拖动窗口未实际改变尺寸，因此没有声称完成连续真实拖拽验证。

本机执行器以低完整性运行，实机采集使用可见窗口的屏幕区域降级。遮挡后的 WGC 采集未在本次环境中验证。
过小、被裁切或看不清网格/卡片的画面不能保证识别；校验失败时应等待有效画面，而不是沿用旧坐标。

## 使用

从项目根目录运行 `启动.bat` 可使用更新后的源码。旧版 exe 不会自动获得源码修改。
新版独立打包文件：`build_artifacts/20261125_adaptive/HuahuaAssistant.exe`，同目录 `build_report.json` 保存源码与产物哈希。
Windows 自动启动接口返回 `ShellExecuteW = 5`（拒绝访问），因此本次未完成打包程序的界面启动与预览实测。
持续验证脚本：`.venv\Scripts\python.exe -B scripts/verify_adaptive_layout.py --seconds 120`。
脚本只采集和分析，在同一进程内保存尺寸变化前后的截图和几何结果，不会点击游戏。
