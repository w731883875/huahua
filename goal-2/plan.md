# Goal 2 Plan

## Objective
为现有画画拼图辅助工具实现“高速捕获 + 快速CV识别 + 桌宠状态机”路线，使桌宠能够在约 0.5 秒内基于游戏窗口变化给出可见反馈，同时保留完整 OCR 作为低频校准路径。

## Context
- 项目入口是 `run_app.py`，核心模块在 `huahua_assistant/`。
- 当前工具已经具备游戏窗口捕获、棋盘识别、背包/初始颜料/词条识别、桌宠和真实数据记录。
- 当前瓶颈是完整 OCR/全量识别慢，实战需要快速反馈。
- 用户明确要求不要接管设备输入，桌宠不能遮挡或污染识别。
- 用户希望桌宠“看起来智能”：能跟随游戏窗口实时变化移动、指向或展示状态。

## Default Assumptions
- 保持外部视觉辅助，不自动点击游戏、不控制鼠标键盘。
- 先做可运行、可观测、可回退的 0.5 秒级快速感知框架，再逐步提升识别准确率。
- 高速捕获后端优先设计为可选：现有 `PrintWindow/mss` 继续可用，新增后端不可用时自动回退。
- 真实学习记录继续只保存可信真实识别，不保存模拟数据。
- OCR 不进入高频循环，只在新初始颜料、词条文字或完整校准时触发。
- 本目标可能需要多轮推进；每轮只执行 `tasks.md` 中第一个未完成任务。

## Requirements
- 游戏窗口捕获应尽量不被桌宠污染。
- 快速识别目标是约 0.5 秒内完成一次轻量状态更新。
- 快速循环必须输出耗时拆分，方便判断瓶颈在捕获、CV、推荐还是渲染。
- 桌宠状态机需要可解释，至少能表达观察中、推荐背包、推荐地块、推荐词条、等待落笔、结算/完成等状态。
- 保留完整识别按钮作为慢速校准路径。

## Execution Approach
1. 先盘点现有捕获、快速识别、桌宠补丁和耗时记录路径，建立基线。
2. 抽象高速捕获接口，新增可选快速后端和回退机制。
3. 建立 `FramePump` 或等价循环，只保留最新帧，避免排队延迟。
4. 建立轻量 `FastVision` 输出，优先复用现有棋盘位置、背包 ROI、词条面板 ROI。
5. 建立事件检测层，识别画面变化、新颜料、背包出现/消失、选中态、词条阶段等。
6. 建立桌宠状态机和节流渲染，让桌宠动画连续但识别更新低频。
7. 增加调试面板和日志，展示捕获/快速识别/推荐/桌宠渲染耗时。
8. 保持质量门：不可信快速识别不写入高分轨迹。

## Validation
- 运行 Python 编译检查。
- 对现有 `runtime/capture.png` 或最新捕获帧做快速路径回归。
- 检查耗时字段是否能显示捕获、CV、推荐、桌宠更新耗时。
- 检查桌宠/标记仍然鼠标穿透，不阻挡游戏点击。
- 检查完整 OCR 路径仍能运行。

## Risks
- Windows 捕获后端可能受显卡、权限、全屏模式影响，需要回退。
- 捕获窗口与实际客户区坐标可能存在边框/DPI 差异，需要继续通过坐标调试校准。
- 快速 CV 初期准确率可能低于完整 OCR，需要明确“不可信不保存”。
- 桌宠高频更新可能闪烁，需要节流和状态去抖。
- 引入新依赖可能安装不顺畅，应优先可选导入，并保留现有后端。

## Rollback
- 新后端必须可配置禁用。
- 保留现有完整识别和快速识别入口。
- 如果高速捕获不可用，自动回退到现有 `capture_target`。
- 不修改真实数据格式的核心语义；新增字段应兼容旧记录。
